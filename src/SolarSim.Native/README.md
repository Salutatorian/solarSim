# solarSim Native Engine

This directory contains a native C++ implementation of the solarSim electrical and geometric engine. It mirrors the C# domain in `src/SolarSim.Domain/` and is designed to be fuzzed as part of the Fenrir / ClusterFuzzLite submission.

## Architecture

The native engine is organized into focused modules:

- **solar_panel** — module definitions, instances, ports, built-in catalogs
- **electrical_graph** — panels, equipment, connections, series-string discovery
- **string_calculation** — series string and project-level electrical math
- **voltage_drop** — DC conductor voltage-drop and ampacity checks
- **temperature_derating** — STC → site-temperature voltage and power adjustments
- **string_sizing** — series-string length advice vs inverter limits
- **mppt_compatibility** — string voltage checks against MPPT and max DC windows
- **connection_validator** — DC topology validation (polarity, connectors, gender, occupancy)
- **wire_route** — routed polyline wire lengths and voltage-drop estimates
- **wire_gauge_format** — AWG gauge tables, battery-cable gauges, ampacity
- **roof_geometry** — 2D CAD geometry: snapping, polygons, containment, area
- **roof_surface** / **roof_document** — multi-surface roof layers with setbacks and obstacles
- **racking_layout** — rail, attachment, and clamp estimates from panel layouts
- **panel_port_layout** — PV+/PV- port positions for a placed panel
- **project_file** — compact binary SOLP project loader
- **json_project_serializer** — JSON parser for the `.solarproj` export format
- **solar_project_state** — top-level project container for definitions, graph, and roof
- **site_conditions** — location, climate presets, temperature, tilt/azimuth, PSH, derate
- **production_estimate** — monthly and annual energy production estimates
- **design_report** — HTML/SVG design report generation
- **bom_schedule** — bill of materials and wire schedule
- **equipment_library** — inverter, battery, combiner, and disconnect definitions
- **units** — unit conversion helpers

## Relationship to the C# application

The native engine is a sibling implementation of the same solar design domain. It can be used for:

- High-performance parsing and validation of project files and module catalogs
- Headless fuzzing of geometry, electrical topology, and serialization code
- Future P/Invoke integration from the C# application for performance-critical paths

## Building

See `fuzz/README.md` for the ClusterFuzzLite build instructions. The build script at `.clusterfuzzlite/build.sh` compiles every `src/SolarSim.Native/src/*.cpp` file and links it against every `fuzz/*_fuzzer.cpp` harness.

## Testing

Each module has a corresponding fuzzer harness in `fuzz/` and a seed corpus in `fuzz/corpus/<harness>/`. The corpora are generated by `Tools/generate_fuzzing_corpus.py`.
